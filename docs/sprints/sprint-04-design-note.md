# Sprint 4 scheduler design decisions

Status: implementation planning note. No hardware behavior is asserted here. Tags describe the evidence available from repository specifications and static stock-firmware analysis.

| Question | Decision | Evidence status |
|---|---|---|
| Shift/latch register layout | Treat PB10/PB9 as DATA/CLK into a shift path and PB8 as an active-low latch; PB11 is the independent heater strobe. Do not assume a second independently writable row buffer exists in Pinbridge. | **Confirmed** for Pinbridge pin roles and active-low latch from current driver/demo; **inferred** that shifting does not disturb the latched output, pending head-driver schematic or measurement. |
| Shift duration | Keep the existing `PB_TUNE_HEAD_SHIFT_TIME_US=3000` as a planning estimate only. The firmware's 384-bit bit-bang loop uses nominal 1 us waits plus GPIO overhead; this does not establish a 3 ms measured duration. | **Confirmed** that 384 bits are shifted in byte order 0..47, LSB-first in stock analysis; **inferred** duration. No scope measurement. |
| Timer resolution | Existing scheduler time source is `millis()` and the legacy step poll quantizes periods to milliseconds. The stock heat timer is statically derived as roughly 30 us/tick; neither is a measured Pinbridge scheduler timer. Keep all heater use behind Sprint 3 gates; do not advertise sub-ms effective timing until a real timer backend exists. | **Confirmed** for current software clock granularity and gate constants; **inferred** for stock ~30 us tick from timer setup; no hardware measurement. |
| Pre-shift next row | Do **not** pre-shift. A conventional latch suggests the active latched image may be isolated, but the exact head register topology and shift-vs-latch electrical behavior are not verified well enough to prove it safe. Serialize shift/latch/heat for now and report the throughput ceiling as unknown/low. | **Inferred**, deliberately conservative. |
| Four events per stock row | Stock static analysis supports four copies/operations per logical stock row: four shift/latch/heat windows and four phase advances. TBP `ROW` remains one protocol row with caller-specified steps; do not silently multiply its steps or burn. A future stock-compatibility layer must explicitly map one TBP row to four events. | **Confirmed** as a static-analysis finding in `docs/stock-print-scheduler-handoff.md`; not hardware-measured. **Confirmed** TBP v1 currently defines independent `steps` and `slices` per ROW. |
| Dot/bit order | Preserve the currently implemented TBP mapping: mask byte 0 first and bit 7 as the logical leftmost dot. Stock shift routine is byte 0..47, bit 0..7 (LSB-first); therefore the wire bit order differs from the logical mask's dot numbering unless the head driver remaps it. Do not reverse bytes/bits without evidence. | **Confirmed** for software/spec conventions and static stock shift order; physical dot order/polarity **inferred/unverified**. |
| Paper direction | Preserve TBP convention: positive steps mean feed-forward/printing; negative means retract. The eight-state half-step phase is persistent; reverse changes phase traversal, not the logical sign convention. Do not claim physical paper direction from software alone. | **Confirmed** as TBP convention and code behavior; physical direction **unverified** by Sprint 4. |
| Phase order / continuous motion | Preserve the stock eight-state phase table and remembered phase index. Do not reset phase at ROW/MOVE boundaries. Given serialized row work and no proven look-ahead shift safety, continuous motion across adjacent queued rows is an implementation goal but cannot be claimed until the scheduler actually overlaps motion with row preparation. | **Confirmed** for the persistent phase state and table in source; overlap capability **not yet confirmed**. |
| COLD_START / STRETCHED / LATE telemetry | Set COLD_START only when a moving ROW starts while no step timer/motion is active. Keep STRETCHED and LATE clear until effective period extension and missed row deadlines are measured by the scheduler itself. Do not infer lateness from host round-trip timing. | COLD_START is **detectable from current state**; STRETCHED/LATE **not currently detectable accurately**. |

## Implementation guardrails

- No `cargo test`, local firmware build, or hardware flash.
- Do not modify `pb_tuning.h` safety values, and never enable direct PB11-high via `MOD`/`SET`.
- All ROW heat remains routed through the Sprint 3 sensor, temperature, battery, paper, slice and duty checks.
- Remote CI and deterministic mocks prove software properties only, not head polarity, physical feed direction, burn duration, or safe thermal limits.
