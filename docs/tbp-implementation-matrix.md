## Known draft ambiguities to resolve before claiming conformance

1. **Resolved — INFO length wording:** INFO body is 38 bytes; enclosing STATUS DATA includes the state byte for 39 bytes total.
2. **Resolved — frame maximum:** max wire line is 520 hex characters plus LF; C allocates extra NUL storage. C transcript covers the exact 520-character frame and overlong discard/resync.
3. **Resolved — duplicate replay:** a duplicate receives ACK plus state-only STATUS; an ID outside the retained 127-ID history receives ERR SEQ and never re-executes.
4. **ROW timing/result:** §7.5 defines `steps` as i8 and DONE telemetry fields; §8 requires continuous step timing, independent heater timer and look-ahead. Current C performs heat before stepping and reports placeholders/nominal values. Sprint 4 must define measurable acceptance without pretending current behavior conforms.
5. **Safety constants:** §9 marks key thermal/duty/guard values TBD. Until owner-approved values and real sensor acquisition exist, no heater-enabled physical test should be treated as safe validation.
4. **ESTOP semantics:** §3.1 says ESTOP skips session and sequence checks; §6.3 requires heater off immediately. A synchronous parser cannot meet this while blocked in ROW/MOVE/DWELL. Sprint 2 must implement an interruptible execution architecture.
5. **CONFIG defaults/effects:** the spec lists heartbeat, idle-hold and link-timeout settings, but current C does not consistently apply them. Specify session persistence and test effective behavior rather than echo-only replies.

## Test evidence boundaries

- `host/pinbridge/bun/tbp.test.ts` and `server.test.ts`: CRC/framing vectors, malformed frame rejection, signed MOVE payload, INFO decoding, lost ACK/STATUS retries, retry exhaustion, sequence resync, serialized commands, disconnect cleanup and HELLO ID reset.
- `firmware/apps/pinbridge/tests/transcripts/`: shared C golden transcripts cover HELLO, sequence/future-ID recovery, wrap, duplicate ROW/MOVE/COILS side effects, history eviction, malformed hex, embedded CR, max-length and overlong-line resynchronization.
- These tests establish Sprint 1 protocol reliability only; they are **not** evidence of full TBP v1 conformance or hardware behavior.

## 2026-11-03 control-plane and watchdog follow-up

Host and firmware now share a tested `STEPS_PER_MM` / `PB_TUNE_STEPS_PER_MM` assumption of 32 half-steps/mm; ruler calibration is still pending. Boot wiggle is derived from 5 mm, waits for stable paper presence, and pauses with coils held between legs and before release; direction/distance still need hardware confirmation. A 900 ms non-timed executor progress watchdog now fails stalled MOVE/ROW jobs safely; dedicated stall transcripts cover a lost step-timer ISR. RX overflow now discards through the next newline, and HELLO recovery retries on the open UART after clearing partial input; physical USB recovery remains unverified. CI now injects the source SHA prefix into HELLO `build_id` and records the full SHA in BUILD-INFO; actual SDK compilation remains pending CI. The host displays Celsius using a generated copy of the stock thermistor table, checked against the firmware header. Heated solid rows split total burn into four slices, enforce the 2500 µs per-slice ceiling, and remain disabled until sensor/safety gates are valid; heater hardware operation is still unverified. The step timer now uses the SDK high-priority 1 ms timer only while moving; the exact BR23 SDK build and hardware timing remain unverified. The protocol defines a 50 ms ACK/ERR response bound on a healthy link. `tbp-control-plane-full-queue.txt` covers STAT/CONFIG/FLUSH/HELLO with all credits occupied; `tbp-estop-busy.txt` covers ESTOP at full queue. STAT is tested during DWELL, ROW preparation/motion, HOT_WAIT and DUTY_WAIT. `tbp-control-plane-bound.txt` checks explicit simulated blocking delay; this does not measure RTOS or USB latency.


COILS during queued/running work is accepted as a no-op and leaves motor outputs untouched (`tbp-coils-busy-noop.txt`). The legacy 5-second watchdog is now suppressed while a TBP session is active; configured TBP link timeout remains the session work-cancellation mechanism. C transcript `tbp-no-legacy-watchdog.txt` proves a long DWELL remains active and STAT responds after the old watchdog threshold; `tbp-link-timeout.txt` covers configured timeout cancellation with session retention. This is source-level simulation evidence, not firmware-build or hardware evidence.
